# ADR-004：酒店 POI、估算价格与实时库存严格分层

- 状态：Accepted
- 日期：2026-08-20

## 背景

地图 POI 可以提供酒店名称、位置、类别和部分联系方式，但不能证明某日期的实时房价、房态、取消政策或可预订性。个人项目若把模型估算或 POI 信息包装成实时库存，会形成不可验证的产品与简历主张。

## 候选方案

1. 用模型估算酒店价格并显示为实时价格；
2. 抓取公开页面模拟库存；
3. 明确区分酒店候选、版本化预算估算和授权供应商库存；V1 不预订。

## 决策

采用方案 3。V1 允许：

- 用高德 POI 生成位置可追溯的住宿候选；
- 使用用户输入价格或明确标注的 fixture/估算区间进行预算演示；
- 展示来源、获取时间、数据模式和“不代表可预订”的提示。

V1 禁止声称实时房价、剩余房量、下单或支付。预算校验只计算带明确来源与口径的 `CostItem`，未知住宿价格必须保留为未知或请求用户补充，不能由模型静默填充。

## 后果

- 产品展示不如接入真实 OTA 完整，但数据真实性边界可解释、可测试。
- 酒店推荐仍可体现地理位置、路线与偏好匹配能力。
- 面试和 README 只能使用“住宿候选”“估算区间”，不能使用“实时酒店库存”。

## 重新评估条件

只有获得有授权、许可和稳定 sandbox 的酒店供应商 API，并建立 contract tests、时间戳和失败降级后，才增加实时价格或库存能力。
